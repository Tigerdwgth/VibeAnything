# PRD: 顶部分屏入口与目录路径修复

## Introduction

在 Web Dashboard 页面上部增加 tmux 分屏入口，允许用户直接通过页面触发 tmux 自带的上下左右分屏能力；同时修复目录栏和相关启动流程中的路径推断 bug，避免把实际属于当前登录用户的目录错误写成 `/root/...`。该功能用于减少手动输入 tmux 命令的成本，并保证不同开发机、不同登录用户下的目录行为一致。

## Goals

- 在页面上部提供 4 个明确的分屏入口：上、下、左、右
- 分屏操作复用 tmux 原生 `split-window` 能力，而不是自定义前端布局
- 新分屏创建后自动进入当前项目目录并启动默认 shell
- 修复目录栏自动输入错误路径的问题，不再错误写入 `/root/...`
- 统一修复所有涉及目录推断、终端创建、分屏启动的路径来源逻辑

## User Stories

### US-001: 顶部显示四个分屏按钮
**Description:** 作为用户，我希望在页面顶部直接看到上、下、左、右四个分屏按钮，这样我可以快速创建 tmux pane，而不需要手动输入 tmux 命令。

**Acceptance Criteria:**
- [ ] Dashboard 顶部新增 4 个可点击入口，分别对应上分屏、下分屏、左分屏、右分屏
- [ ] 每个按钮的文案或图标能明确表达方向，用户无需猜测
- [ ] 按钮放置在页面顶部现有操作区中，不遮挡其他核心操作
- [ ] 移动端和窄屏下按钮仍可见且可点击
- [ ] Typecheck/lint passes
- [ ] Verify in browser using dev-browser skill

### US-002: 使用 tmux 原生上下左右分屏
**Description:** 作为用户，我希望页面上的分屏操作直接调用 tmux 原生分屏能力，这样新 pane 的行为与我手动在 tmux 中执行命令保持一致。

**Acceptance Criteria:**
- [ ] 点击“上分屏”时，系统调用 tmux 原生命令创建位于当前 pane 上方的新 pane
- [ ] 点击“下分屏”时，系统调用 tmux 原生命令创建位于当前 pane 下方的新 pane
- [ ] 点击“左分屏”时，系统调用 tmux 原生命令创建位于当前 pane 左侧的新 pane
- [ ] 点击“右分屏”时，系统调用 tmux 原生命令创建位于当前 pane 右侧的新 pane
- [ ] 分屏失败时，页面给出可识别的错误反馈，而不是静默失败
- [ ] Typecheck/lint passes

### US-003: 新分屏默认进入当前项目目录并启动 shell
**Description:** 作为用户，我希望新建的 pane 自动切换到当前项目目录，并直接进入默认 shell，这样我可以马上开始操作。

**Acceptance Criteria:**
- [ ] 新 pane 创建后自动切换到当前项目目录，而不是停留在 tmux server 默认目录
- [ ] 新 pane 启动的是目标开发机上的默认 shell，而不是前端硬编码的某个 shell
- [ ] 当前项目目录不可用时，系统显示错误信息，并且不伪造错误路径
- [ ] 分屏后目录与当前页面上下文一致，用户无需手动再 `cd`
- [ ] Typecheck/lint passes

### US-004: 修复目录栏自动输入为 `/root/...` 的问题
**Description:** 作为用户，我希望目录栏自动填入的是当前登录用户实际可用的目录，而不是错误的 `/root/...`，这样我才能直接启动会话或进入目录。

**Acceptance Criteria:**
- [ ] 目录栏自动填充值不再硬编码为 `/root/...`
- [ ] 对于非 root 用户，目录栏默认路径基于该用户在目标开发机上的实际 home 目录生成
- [ ] 对于 root 用户，系统允许实际 home 目录为 `/root`，不做错误替换
- [ ] 不同开发机登录不同用户时，目录栏均能显示各自正确的默认目录
- [ ] Typecheck/lint passes
- [ ] Verify in browser using dev-browser skill

### US-005: 统一修复所有目录推断相关入口
**Description:** 作为用户，我希望所有依赖目录推断的入口都使用同一套正确逻辑，这样分屏、打开终端、目录栏输入不会出现彼此不一致的情况。

**Acceptance Criteria:**
- [ ] 目录栏默认值、从目录树启动终端、从 session 恢复/新建终端、分屏创建 pane 等场景共用统一的目录解析逻辑
- [ ] 系统不会在一个入口使用真实目录、另一个入口仍使用 `/root/...`
- [ ] 当目标机器无法返回当前用户 home 目录时，系统使用明确且可解释的回退策略
- [ ] 至少补充覆盖非 root 用户与 root 用户两类场景的测试或等价验证
- [ ] Typecheck/lint passes

## Functional Requirements

- FR-1: Dashboard 顶部必须提供 4 个分屏入口，对应上、下、左、右四个方向。
- FR-2: 分屏入口触发的后端行为必须基于 tmux 原生命令 `split-window` 实现，不得用前端模拟分栏替代。
- FR-3: 系统必须支持 tmux 的上下左右分屏语义，方向行为与用户在 tmux 中手动执行命令一致。
- FR-4: 新创建的 pane 必须自动切换到当前项目目录，并在该目录下启动目标开发机的默认 shell。
- FR-5: 当前项目目录的来源必须与当前页面上下文一致；如果用户是从某个 session、目录树或目录栏发起操作，系统必须使用对应上下文目录。
- FR-6: 系统不得硬编码 `/root` 或 `/home/<固定用户名>` 作为默认目录来源。
- FR-7: 系统必须根据目标开发机当前登录用户的实际 home 目录生成默认路径；若当前用户是 root，则 `/root` 必须被视为合法 home。
- FR-8: 目录栏默认值修复必须覆盖所有目录推断相关场景，包括但不限于目录栏自动填充、创建新终端、恢复终端、从目录树启动、tmux 分屏启动。
- FR-9: 当系统无法确定实际 home 目录或目标目录不可访问时，必须返回明确错误或使用受控回退逻辑，不得静默生成错误路径。
- FR-10: 分屏操作和目录修复不得改变现有 tmux session 管理模型，不得导致已有 session/pane 被意外关闭。

## Non-Goals

- 不实现浏览器内部自定义拖拽分栏布局
- 不增加除上下左右之外的其他 pane 布局模板
- 不在本 PRD 中规定 subagent、worktree、代码审核、部署流程
- 不重构整个终端系统或替换 tmux
- 不处理与目录推断无关的其他历史路径显示问题

## Design Considerations

- 分屏按钮应位于 Dashboard 顶部现有操作区，保持与当前顶栏按钮风格一致
- 四个方向建议使用“上分屏 / 下分屏 / 左分屏 / 右分屏”文案，或使用足够明确的箭头图标
- 失败提示需要让用户知道是“tmux 分屏失败”还是“目录解析失败”

## Technical Considerations

- 前端已有 `Dashboard.jsx`、`TerminalPanel.jsx`、`FileBrowser.jsx`、`SessionTabs.jsx` 等目录和终端相关入口，PRD 对这些入口统一提出目录一致性要求
- 后端或 relay 层需要承接新的 tmux 分屏动作，并把方向与目录参数传给目标开发机
- 实际 home 目录建议通过目标开发机运行环境获取，例如当前进程用户信息、环境变量或系统用户信息，而不是前端拼接字符串
- 目录修复需要特别考虑 root 用户与普通用户共存的情况，避免把合法 `/root/...` 错误改写成 `/home/...`
- 若项目已有测试框架，应优先为路径解析逻辑增加自动化测试

## Success Metrics

- 用户可以在页面顶部 1 次点击完成任一方向的 tmux 分屏
- 新建 pane 后无需手动执行 `cd` 即可开始工作
- 非 root 开发机不再出现错误的 `/root/...` 自动填充
- root 开发机保持合法 `/root/...` 行为，不引入回归
- 所有目录相关入口的默认路径表现一致

## Open Questions

- 顶部四个分屏入口最终使用纯文字、纯图标，还是图标加文字的组合，仍可在实现时按现有 UI 风格细化
